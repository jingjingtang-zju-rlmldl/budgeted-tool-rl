# Continued local tool-policy LoRA

This experimental checkpoint continues the repository's v1 adapter on new
single-action, long-chain and recovery supervision. It is intended for this
controlled English lookup schema with actual tool observations. It is not
an official Qwen model or a general-purpose agent.

- Backbone: [Qwen/Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B), pinned
  revision `c1899de289a04d12100db370d81485cdf75e47ca`.
- Initialization: the included `results/sft-v1/training/adapter`, verified by
  both file hashes and the loaded adapter tensor-state hash. No fresh LoRA
  initialization or smoke-probe weights are used.
- New data: 300 executed oracle trajectories, 990 next-action targets,
  including 80 immediately following real recoverable errors. Forty
  within-train goal pairs produce 260 independent fact groups. All new
  train/dev/test/signal facts exclude historical entities and private values.
- Training: frozen BF16 backbone; 1,146,880 FP32 q/v LoRA parameters;
  rank 8, alpha 16, dropout 0.05; AdamW lr=1e-4, accumulation 8,
  microbatch 1, clip=1, seed 42, one epoch / 124 optimizer steps.
- Supervision: assistant-only next JSON action plus EOS, with prefix labels
  masked. No generated or invented tool result is a supervised target.
- Checkpoint choice: fixed final epoch. No test or reward-signal selection.
- Interface: `prompts/protocol.txt`; one action per assistant turn, then an
  observation from the real environment. Use the repository runner rather
  than asking the model to simulate a full assistant/tool transcript.
- Evidence: [training manifest](training/manifest.json),
  [training audit](training-audit.json), [summary](summary.json),
  [Chinese analysis](analysis.zh-CN.md), [reproduction](reproduce.md).

The small adapter is `training/adapter/adapter_model.safetensors`; its exact
SHA-256 and the unchanged v1 checkpoint hashes are recorded in the training
manifest. The v2 adapter contains the full continued LoRA parameters: load it
on the base once, without stacking the v1 adapter. Base weights are excluded.

## Portable loading

Download the pinned snapshot and pass its actual local path explicitly.
The PEFT-generated adapter configuration retains the original machine's
base path as provenance; that path is not a portable download location.

```python
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel

snapshot = "path/to/pinned/Qwen3-0.6B/snapshot"
tokenizer = AutoTokenizer.from_pretrained(snapshot, local_files_only=True)
base = AutoModelForCausalLM.from_pretrained(
    snapshot, local_files_only=True, dtype=torch.bfloat16,
    attn_implementation="sdpa",
)
model = PeftModel.from_pretrained(
    base, "results/sft-v2/training/adapter", is_trainable=False,
    local_files_only=True,
).to("cuda").eval()
```

The autogenerated `training/adapter/README.md` is preserved because the
checkpoint files are frozen before evaluation. This model card documents
the experiment without rewriting its checkpoint bytes.

## Limits

Only one training seed and a synthetic deterministic database schema are
studied. Private fact and wording holdouts within that schema do not
establish transfer to unseen tools, noisy services, multilingual requests,
open-ended planning or RSI. Long-chain/error compositions in the signal
set test a limited form of compositional transfer. Four samples per task
are a diagnostic, not a guaranteed RL improvement estimate. No RL update,
paid API request or cloud GPU is part of this run. The reported memory
applies to actual sequence lengths and this small LoRA workload; it does
not establish the joint memory cost of RL rollouts and optimization.
